# Troubleshooting the SQL Connector

Each entry is titled by what you see on a run, an Activity or a connection test. For a run that ends with a warning or an error whatever the Connector, see [Troubleshooting Synchronisation](../administration/troubleshooting-synchronisation.md).

## :material-lan-disconnect: "Unable to connect. Message: ..."

The database driver's own message follows. A wrong host or blocked port times out after the Connection Timeout; a wrong database name, service name or SID is rejected immediately in the database's own words; a wrong password is an authentication failure. On Oracle, check you have chosen the right form (service name or SID) as well as the right value.

## :material-certificate-outline: The connection test fails on the certificate (SQL Server)

See [When the connection test fails on the certificate](jim-sql-connector-security.md#when-the-connection-test-fails-on-the-certificate).

## :material-eye-off-outline: "Object Type 'X' reads from HR.TABLE, which this database account cannot see"

The name or schema is wrong, or the account has not been granted `SELECT` on it. On Oracle, grants are per table; see [Database account permissions](jim-sql-connector-security.md#database-account-permissions).

## :material-table-multiple: "Object Type 'X' names 'TABLE', which exists in more than one schema"

Add `"schema"` to that Object Type.

## :material-table-column-remove: An attribute is missing after the schema import

Check the import's warnings: a column whose type JIM cannot synchronise is named there. Expose it through a view that casts it to a supported type.

## :material-numeric: "The value has a fractional part, and this attribute's data type is Number"

The column holds fractional values but the attribute's type is a whole number, usually because the type was changed on the Schema tab. Change it to Decimal, or correct the source data.

## :material-import: A Delta Import ran as a Full Import

Expected on the first run, and after changing the Delta Import Mode. If it happens every time, read the warning on the Activity for the reason.

## :material-delete-outline: Deleted rows are not removed by a Delta Import

Watermark Column mode cannot see deletions. Use a change-log table, or schedule a periodic Full Import. See [Delta Import with a watermark column](jim-sql-connector-delta-import-watermark.md).

## :material-export: An export reports "No row was written ... though the database raised no error"

A trigger or rule on the table discarded the insert, or the account cannot write to the table. Check the table's triggers and the account's grants.

## :material-pencil-off-outline: An export reports "No row ... is identified by this Connected System Object's external ID"

The row was deleted or re-keyed outside JIM. Run a Full Import to bring JIM back in line with the table.

## :material-database-alert-outline: An Oracle export reports "returned no value for its anchor column"

The table's key is neither flowed by a Synchronisation Rule nor generated by the database. Back the column with a sequence-based default or an identity column, or flow the key from JIM.

## :material-clock-alert-outline: Dates are out by an hour

The column carries no offset and the Database Time Zone does not match what the application records. Set it to the zone the application uses; columns that carry their own offset are unaffected.

## :material-lifebuoy: Still stuck?

Collect these before asking for help:

- **The database and its version,** and whether JIM connects with encryption.
- **The run's Activity,** with its message and one failing execution item's error.
- **The worker's log from the time of the run:** `docker logs jim.worker`, or `sudo podman logs jim-worker`.
- **The Object Types document,** and for a permission problem the account's grants on the tables involved; leave its password out.

Then ask in the [Q&A](https://github.com/TetronIO/JIM/discussions/categories/q-a) category of GitHub Discussions, or open a [GitHub Issue](https://github.com/TetronIO/JIM/issues) for a bug.
